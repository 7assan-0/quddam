**القرار: NO-GO لإتاحة Beta لمستخدمين خارج بيئة الاختبار المحلية حتى إغلاق البوابات أدناه أو اعتماد نطاق أضيق صراحةً.** هذا المستند لا يلغي نتائج الاختبارات الوظيفية المحلية، ولا يعد موافقة دمج أو نشر أو تشغيل دفع. نتائج PostgreSQL وChrome والفحوص على SHA النهائي تُسجّل في تقرير Beta النهائي؛ تدقيق الاعتماديات هنا ليس بديلًا عنها.

## S1 — اعتماديات التشغيل: تصحيح أمني حساس ينتظر الموافقة

الإصدارات المثبتة موضحة في [package.json](../package.json) الأسطر 38 و45 و60 و65، وكتل `node_modules/next` و`node_modules/source-map-js` في [package-lock.json](../package-lock.json).

| الحزمة الحالية | تنبيهات التدقيق ومجالها | حالة الإثبات |
| --- | --- | --- |
| `next@16.3.6`، اعتماد إنتاج مباشر | High؛ ستة تنبيهات registry تخص cache/Draft Mode وSSG/ISR وMCP التطويري ومسارات metadata image وImage Optimization | وجود إصدار ضمن النطاق المتأثر مؤكد؛ استغلال هذه المسارات في قدّام **NOT RUN**، وكل تنبيه له شروطه |
| `source-map-js@1.2.1`، اعتماد إنتاج انتقالي | High؛ إنهاك event loop عبر indexed source-map section offsets؛ يأتي أيضًا من `next → postcss@8.5.23 → source-map-js` | تثبيت الحزمة في شجرة الإنتاج مؤكد؛ مرور مدخل غير موثوق إلى parser وقت تشغيل قدّام غير مثبت |

روابط التنبيهات العامة التي أعادها التدقيق:

- Next: [Draft/cache](https://github.com/advisories/GHSA-3w37-wq28-93x7)، [SSG/ISR](https://github.com/advisories/GHSA-4jqv-mc3x-m676)، [MCP التطويري](https://github.com/advisories/GHSA-39w2-rjm5-chcv)، [metadata image](https://github.com/advisories/GHSA-f87g-xv8r-7p7x)، [cache substitution/DoS](https://github.com/advisories/GHSA-mcj8-r9mp-w47p)، [Image Optimization SSRF](https://github.com/advisories/GHSA-cjq9-62q9-8jv4).
- Source maps: [GHSA-68fv-2mgg-jv7q](https://github.com/advisories/GHSA-68fv-2mgg-jv7q).

**القرار المقترح للمالك، ولم يُنفذ:** الموافقة على تصحيح اعتماديات مستقل ومحدود يحدّث عائلة `next` و`@next/env` و`eslint-config-next` معًا إلى `16.4.2`، ويُحدّث قفل `source-map-js` إلى `1.2.2` أو إصدار متوافق أحدث بعد مراجعة النطاقات الفعلية. لا يضاف اعتماد إنتاج مباشر أو override شامل لمجرد إسكات التدقيق. لا يُستخدم اقتراح `npm audit fix --force` تلقائيًا؛ بعض اقتراحات التدقيق تعيد عائلة ESLint/Next إلى إصدار رئيسي أقدم أو ترقي Tailwind ترقية رئيسية.

تحققت قراءةً من registry بالأمر `npm view <exact-package@version> version engines peerDependencies dependencies --json` لكل من `next@16.4.2` و`@next/env@16.4.2` و`eslint-config-next@16.4.2` و`source-map-js@1.2.2`، وكانت جميعها موجودة وExit 0. الإصدار `16.4.2` خارج نطاقات Next المتأثرة التي أعادها تدقيق هذا اليوم، و`1.2.2` خارج نطاق تنبيه source-map المذكور. قد تتغير التنبيهات لاحقًا؛ يلزم تدقيق جديد عند التنفيذ.

Node المحلي `24.19.0` وReact/React DOM `19.2.3` وESLint `9.38.0` تحقق نطاقات engines/peers المنشورة للإصدارات المقترحة. هذا **توافق metadata فقط**؛ لم أُنشئ lockfile بديلًا، ولم أختبر resolution أو build أو سلوك Next الجديد.

معيار إغلاق S1 بعد الموافقة: diff حزم وقفل محدود ومفسّر، وتثبيت نظيف، وPrisma generate، والتدقيقان من جديد مع تفسير أي متبقٍ، وجميع اختبارات الوحدة وPostgreSQL والسباقات وTypeScript وLint وBuild. تعاد رحلة Chrome الحقيقية والدعوات وRSVP وNight والبطاقة العربية والشلّة، وفحوص flags والمصادقة وخصوصية الترويسات، على SHA جديد واحد. تقرأ وثائق Next المثبتة الجديدة قبل أي تعديل API. لا تدخل تغييرات دفع أو أسعار أو migration تاريخية أو دمج PR #9 في هذا التصحيح.

## S2 — اعتماديات أدوات الاختبار والبناء

`vitest@4.0.4` اعتماد تطوير في القفل، ويجمع تنبيه Critical خاصًا بخادم Vitest UI وتنبيه path traversal في `@vitest/mocker`. الروابط: [UI arbitrary file read/execute](https://github.com/advisories/GHSA-5xrq-8626-4rwp) و[redirect mock path traversal](https://github.com/advisories/GHSA-82fw-gwwq-j7x9). لم يُشغل خادم Vitest UI؛ الاختبارات تستخدم `vitest run`. هذا يقلل تعرض سيناريو UI أثناء هذا الاختبار، ولا يثبت معالجة الاعتماد نفسه.

بقية عقد تدقيق التطوير تشمل `@vitest/mocker`، و`postcss`، و`postcss-nested`، و`postcss-selector-parser`، و`tailwindcss`، و`braces`، و`chokidar`، و`fast-glob`، و`micromatch`، و`eslint-config-next`، و`@next/eslint-plugin-next`. لا تُجمع هذه العقد باعتبارها استغلالات مستقلة؛ كثير منها ينتقل عبر المسار نفسه. `postcss@8.5.6` المباشر أداة تطوير، بينما `postcss@8.5.23` داخل Next نسخة مختلفة؛ تصنيفهما لا يُستنتج من اسم الحزمة وحده.

**القرار المقترح للمالك، ولم يُنفذ:** تصحيح أدوات محدود إلى `vitest@4.1.12` مع حزم Vitest الانتقالية المتطابقة، ثم معالجة PostCSS وبقية أدوات البناء بمراجعة مستقلة للقفل. تحقق registry فعلًا من `vitest@4.1.12` و`@vitest/mocker@4.1.12`، Exit 0. نطاق Vitest المقترح يقبل Vite `^6 || ^7 || ^8`؛ القفل الحالي يحتوي Vite `7.3.6`، وNode و`@types/node` الحاليان يحققان metadata المطلوبة. هذان الإصداران خارج نطاقَي التنبيه المذكورين وقت التدقيق. لا يعني ذلك أن كل أدوات التطوير أصبحت سليمة.

معيار الإغلاق: تثبيت نظيف يعيد حزم `@vitest/*` إلى عائلة متوافقة، ومراجعة عدم ترقية Vite/ESLint/Tailwind ترقية جانبية غير مقصودة، وإعادة كامل الاختبارات دون حذف assertions أو retries تخفي فشلًا. تعاد كذلك اختبارات PNG الحقيقية، mocks وtimers وSSR وtypecheck وLint وBuild، ويؤكد عدم إدخال UI/watch مستمع إلى إعداد CI. ترقية Tailwind الرئيسية وتغيير التصميم غير معتمدين هنا. تثبيت أو اختبار الإصدارات المقترحة **NOT RUN** حتى الموافقة.

## S3 — حدود الشلّة ليست حد طلبات زمنيًا

[rules.ts](../src/lib/shillatak/rules.ts) الأسطر 6–8 يحدد 20 عضوًا و5 دعوات نشطة و7 أيام للدعوة. [service.ts](../src/lib/shillatak/service.ts) الأسطر 102–120 و160–170 يطبق قفل المجموعة وحد الدعوات النشطة والإلغاء. يمكن للمالك تكرار إنشاء دعوة ثم إلغائها؛ حد الخمس النشطة لا يحد عدد صفوف الدعوات المتراكمة ولا معدل الطلبات. كذلك لا يحد حد الجسم 4096 بايت في [http.ts](../src/lib/shillatak/http.ts) الأسطر 16–21 عدد الطلبات. لم يضف هذا العمل limiter زمنيًا للشلّة.

**قرار المالك المطلوب:** اعتماد حدود ونافذة زمنية لكل فئة كتابة، خصوصًا إنشاء المجموعة، وإنشاء/إلغاء الدعوة، وقبولها، وربط النتائج، مع تحديد ما يحتسب من المحاولات المرفوضة والإعادات الآمنة، ونطاق الحساب/المجموعة/الميزانية الإجمالية. لا أختار أرقامًا نهائية أو سياسة احتفاظ جديدة من تلقاء نفسي.

مقترح قابل للمراجعة بعد القرار: عدادات PostgreSQL ذرية متعددة العمليات، مفاتيح HMAC مفصولة بنطاق `shillatak-abuse-v1` مشتقة من الحساب/العملية/المجموعة، دون تخزين الرمز الخام أو البريد أو IP. لا يعتمد القبول على ذاكرة عملية Next واحدة، ولا يعاد استخدام اسم عملية login بحيث تعطل طلبات الشلّة تسجيل الدخول.

يمكن تقييم إعادة استخدام بنية [AuthAttempt](../prisma/schema.prisma) الأسطر 133–138 والنمط الذري في [auth/abuse.ts](../src/lib/auth/abuse.ts) الأسطر 88–108. **الوظائف الحالية مخصصة للمصادقة** وليست limiter عامًّا؛ يلزم فصل namespace وترتيب الأقفال وسلوك الفشل، وعدم تغيير ميزانيات auth القائمة. يطبق cleanup الحالي احتفاظ 48 ساعة وباتشًا محدودًا في الأسطر 73–83. إعادة استخدام الجدول ستجعل العدادات الجديدة تدخل هذه الدورة أيضًا؛ يلزم تقييم الملاءمة واعتمادها، ولا تنشأ سياسة حذف جديدة أو جدول دائم لمجرد هذا المستند.

معيار الإغلاق: اختبارات حقيقية متزامنة من اتصالين/عمليتين، إثبات عدم تجاوز السقف، وتجدد النافذة بساعة مضبوطة، ورفض 429 واضح و`Retry-After` صحيح، وفشل آمن منقح عند تعطل مخزن الميزانية، وعدم إطالة النافذة بلا نهاية بالطلبات المرفوضة. تختبر محاولات إنشاء/إلغاء متناوبة، والإعادات وفقدان الرد، ولا يتضاعف الأثر ولا يتغير الرصيد. لا تعد هذه الحماية مقاومة كاملة لـDoS موزع أو للحسابات الوهمية.

## S4 — خصوصية السجلات وسياسات البيانات

- تضع مسارات الدعوة `no-referrer` و`private, no-store` و`noindex` في [proxy.ts](../src/proxy.ts) الأسطر 20–24. هذه الترويسات لا تنقح access logs. لا يوجد logger صريح في مصدر الشلّة، لكن Next dev قد يسجل مسارات الطلبات ذات الرمز، ويلزم إثبات تنقيح مسارات الدعوات في أي proxy أو سجلات تشغيل مستقبلية. لا تنشر raw logs أو HAR أو trace أو لقطات لحقل رابط العضوية. تشغيل built server محليًا ليس دليل تنقيح إعداد نشر لم يُنشأ.
- السجلات `ShillaNight` غير قابلة للتعديل/الحذف بواسطة trigger في [migration الإضافة](../prisma/migrations/20261016020000_shillatak_mvp/migration.sql) الأسطر 51–55. المغادرة تزيل العضوية؛ الأرشفة تحافظ على التاريخ. الاحتفاظ والحذف النهائي والتصدير ومعالجة طلب محو البيانات ونقل الملكية تحتاج قرار المالك وتصميمًا مستقلًا. لا تُعطل trigger ولا تُنفذ معالجة SQL التفافية.
- رابط الشلّة قابل لإعادة المشاركة، وأول حساب مؤهل يقبله يستهلكه. حساب قدّام ليس إثبات هوية بشرية أو توثيق بريد. الانضمام يعرض اسم الحساب للأعضاء مع إشعار الواجهة؛ اسم RSVP ليس عضوية ولا سلطة هوست. لا ادعاء بمقاومة كاملة للتلاعب أو Sybil.
- سياسة CSP المرسلة للمتصفح ما زالت `Content-Security-Policy-Report-Only` في [proxy.ts](../src/proxy.ts) السطر 19. فحوص CSP المرشحة لا تعني فرضها. فرضها يحتاج تحققًا منفصلًا للواجهات القائمة.

## حدود القرار النهائي

تصحيحات ربط إيصالات النتائج وإخفاء اسم المجموعة عن حامل الدعوة المغلقة جيدة ضمن حدود اتساق المصدر المخزن؛ بصمة SHA-256 غير الموقعة ليست حماية من مدير قاعدة بيانات يغير البيانات والهاش معًا. تبقى صلاحيات PostgreSQL والتشغيل والنسخ الاحتياطي جزءًا من بوابة الإطلاق.

المراجعة المصدرية بين PR #12 والرأس الأولي لـPR #13 تؤكد عدم تغيير billing أو أسعار الألعاب أو محركات الألعاب الثلاث أو Night core/adapters/service أو migrations التاريخية. إثبات صفر خصم إضافي وعدم تكرار خصم START يأتي من الاختبارات المالية المحلية في التقرير النهائي، وليس من هذا الـdiff وحده.

لا تثبت نتائج CI المالي صلاحية الشلّة أو الشبكات. PR #9 منفصل، ودمجه مع Night غير منفذ؛ اختبارات جهازين على LAN وNAT مختلفين وHTTPS وlauncher الإنتاج والنشر العام **NOT RUN في هذه المراجعة**. كذلك لا تعالج هذه الإضافة audited PENDING-hold resolution أو تشغيل المراقبة والتنبيه أو تحقق التاجر أو بوابات successor release الكاملة. لا اعتماد مرشح قديم ينتقل إلى مصدر PR #13.

لم ينفذ هذا التدقيق نشرًا أو دمجًا أو ترقية حساسة أو تشغيل دفع أو موارد خارجية. التكلفة الخارجية الجديدة **$0**. يستكمل العمل المحلي المصرح به، ثم تعرض قرارات S1–S4 والاختبارات غير المنفذة للمالك قبل أي توسيع للتعرض.
