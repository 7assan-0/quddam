# Host SSE authentication lifetime — Phase 5.0B-2 / H01

The nine dedicated Host SSE routes bind the original authenticated AuthSession ID and user ID, not only the user actor. `currentAuthSession` retains the existing hashed-cookie authentication and suspended-account checks; `currentUser` continues returning only its original user projection. No session identifier, token or hash is sent to a client projection.

`validateActiveAuthSession(sessionId, expectedUserId)` queries that exact session and account and distinguishes ACTIVE, AUTH_INVALID and TRANSIENT_FAILURE. Missing/deleted, revoked, expired, mismatched-owner or suspended-account sessions are invalid. Suspension is the existing disabled-account mechanism; there is no separate enabled flag. Logout revokes the current row; password reset revokes all user sessions. A different valid login cannot authorize the already-open old connection.

A per-connection guard revalidates every 20 seconds: about three additional logical Prisma auth queries per minute, regardless of 250ms Lightning/Ordering polling. The selected account relation is part of that lookup; Prisma's relation query strategy may use a second SQL statement for the user. This is at most approximately six SQL reads per minute, not auth reads per fast tick. Captured expiry is checked locally on each gate, so a known expiry does not wait for the next lookup. A shortened server expiry is detected at the next scheduled lookup. Checks happen before polling and again after awaiting a view, before emitting changed state. A validation result that detects invalidity prevents further private emissions and polling. The initial view is guarded too. The maximum normal revocation delay is approximately 20 seconds plus one existing polling tick and DB response time; in-flight reads that cross the boundary are guarded before emission.

Invalid authentication emits the existing access-ended event and closes, without changing audience or game ownership checks. Transient auth lookup failures emit only `retry: 5000` and close; the client reconnect authenticates normally. No auth row is mutated or permanently invalidated by a lookup error. Existing non-auth gameplay read failures retain their original handling; M07 recovery is outside this phase.

Cancellation/abort wakes and clears the pending delay. Finalization clears scheduled work, detaches the abort handler and closes an authorized connection cleanly. An already in-flight database query cannot be canceled by the Web stream, but its result is discarded after cancellation, and no next query is scheduled.

Affected: social, letter-network, survey-show, secret-word, bluff, ranked, lightning, ordering and court events routes. Category Board display SSE has no Host actor and is unchanged. Room SSE calls roomView/roomAccess/currentUser on each read, already revalidating the original cookie; it is unchanged. Display, participant, juror, clue, buzzer and controller access policies and every projection remain unchanged.

Tests: helper and all nine real route handlers with fake clocks (including transient failures, exact session identity, cadence, cleanup and in-flight projection boundary); five real browser/database scenarios across Letter Network, Lightning and Court cover logout, explicit revocation, expiry, suspension and the actual password-reset endpoint. Original E2E identities and game engines are preserved.
